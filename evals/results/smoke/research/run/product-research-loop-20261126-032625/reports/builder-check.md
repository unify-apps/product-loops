# Builder check: Shutter Invoice, first modules

I read the brief as the person who has to build it alone. These three questions change what gets built. Each has the answer I would take if nobody replies.

## 1. Which country's pages do I read for each rival?
Wave's page names Canadian payroll and no UK. FreshBooks and Bonsai also have US pages, and some have UK pages. Which version I read changes the yes, partial and no cells: VAT, GBP, UK card payments and payroll.
**Default:** read the UK page (en-gb or /uk) wherever one exists. Where there is none, read the .com page and mark a feature that only works in the US or Canada as "partial, not in UK", with the link. Write down which version each row came from.

## 2. Do the "3 ideas no rival has" compete for the top 3 first-release slots?
Need 16 asks for catch-up modules first plus at least 3 new ideas. Need 10 and the "simple" cut cap the first release at 3 modules. If an idea can take a top-3 slot, the release changes.
**Default:** catch-up modules fill the top 3. New ideas are ranked 4 and below. The one exception is a new idea that the persona's core flow cannot work without, such as a wedding deposit followed by a balance invoice. That idea may take slot 3, and the brief says why.

## 3. What counts as a module for a "simple invoicing tool"?
The rivals also sell accounting, payroll, tax filing, proposals, contracts and time tracking. If all of these are rankable modules, the list and the top 3 change.
**Default:** the sheet records every rival feature found, up to the depth limit, so the "done" checks still pass. Only features close to invoicing are ranked as modules: clients, invoices and quotes, getting paid, reminders, deposits and balances, VAT on invoices. Accounting, payroll, tax filing and bookkeeping get sheet rows marked "out of scope: not simple invoicing" and are not ranked.
